✈️ 全球航空市场进入策略分析

BACKGROUND

项目背景

航空创业面临高度复杂的市场环境：航线资源、区域需求、客户价值、运营成本相互影响，仅依靠经验判断难以形成可靠决策。

核心目标：本项目从商业问题出发，搭建数据分析框架，探索 SkyBridge Aviation 的市场进入路径。
THOUGHTS

我的思考

数据分析的价值不只是发现规律，而是帮助回答：

进入哪里？服务谁？如何竞争？

因此没有停留在单指标分析，而是围绕市场规模、客户价值、区域机会和运营策略建立完整分析链路。

PROCESS

核心过程

  • 01 基于 MySQL 完成航空业务数据建模与查询分析
  • 02 分析全球客户分布、收入贡献与市场集中度
  • 03 通过客户价值分层识别不同消费群体
  • 04 构建价格体系与市场进入策略
  • 05 将数据结果转化为商业决策建议
RESULTS

项目成果

  • ✓ 完成 12 阶段数据驱动分析框架
  • ✓ 输出 14 章节战略报告
  • ✓ 从市场结构、客户价值、区域选择等维度提出创业方案

核心图表与产品结论

01 · 全球机场与战略优先级

市场进入决策起点

美国 P1 但 Cabotage 严管 → 首年不碰，列入 3–5 年目标；首年聚焦东南亚–南亚走廊（新加坡 4h 内 6 亿人口、航权自由化）。

非洲 / 太平洋岛国为 P4 长尾，适合第六航权枢纽延伸。CASE WHEN 把机场数量译成 P1–P4 优先级——SQL 服务商业决策最直接的体现。

02 · 收入 vs 基础设施错配

蓝海在「机场多、收入低」

北美收入高但航权壁垒锁死 → codeshare 导流至新加坡枢纽，而非直接经营。

基础设施过剩、收入贡献低的国家 = 二线机场低成本点对点机会；加拿大–亚洲密度低 + 寡头市场 → 战略性抢稀缺洲际资源。这种错配必须靠 SQL 跨表 join + 比例计算才能挖出。

03 · 航线行动矩阵

12 阶段综合 · 决策终态

前 11 阶段 SQL 汇总为一张执行图：每个行动码对应一句管理话术——守护核心时刻、OPTIMIZE 测试 5–10% 提价、REVIEW 90 天退出窗口。

数据分析的终极交付物不是「洞察」，是决策——把数据库直接翻译成可执行计划。

技术方案摘要

01

12 阶段渐进式框架，而非巨型 SQL

暴力做法

200 行巨型 join → 难 debug、易超时、50 维报表没人知道「该怎么办」。

12 阶段

每阶段一个商业问题；描述→诊断→预测→处方；临时表串联成可解释决策链。

判断：框架是把复杂问题拆成 PM 和业务方能跟上的颗粒度——讲不清楚，技术再强也没用。

02

临时表设计：54M → 462K

booking 54.3M 行；5 个阶段都要「每航班总收入」→ 重复 group by 不可接受。Phase 4 建 flight_revenue，一次聚合、100× 压缩，Phase 4–5 复用、Phase 5 末 DROP。

临时表 创建 使用 销毁
flight_revenueP4P4–5P5 末
customer_value_classP5P5, 12P12 末
route_premium_profileP5P5, 12P12 末
passenger_revenueP7P7P7 末
grand_totalP7P7P7 末

判断：识别复用单元、定义生命周期、显式 DROP——产品架构思维，非单纯性能技巧。

03

NTILE 三档粒度，各有所图

  • • NTILE(3) — 客户价值三档 → 行动决策（Premium / Standard / Budget）
  • • NTILE(4) — 价格四分位 → 定价话术锚点「Top 25%」
  • • NTILE(5) — 收入五分位 → 验证 Pareto 80/20

实证 Top 20% 仅贡献 23.44% 收入 → Pareto 失效，战略转向规模化覆盖而非高端会员。判断：工具参数匹配业务颗粒度。

04

CTE 优先，可读性 > 极致简洁

嵌套子查询

从内到外反向解析；debug 难；业务方看不懂。

WITH … AS (CTE)

阅读顺序 = 思考顺序；每个 CTE 有名字即文档；可组合拆分。

判断：SQL 写给下一个读代码的人（含三个月后的自己）。

05

行业经验写进 CASE WHEN

权重在文档里

分析师各用各的权重 → 结果不可比；更新要手算历史；不可审计。

权重在 SQL 里

雪 ×3 / 雷暴 ×2 / 风暴雹 ×2 / 雾霾 ×1 → 可复现、可审计；改一个数字全局更新。

判断：把业务规则编译成机器可执行代码——数据产品是产品，数据报告是 Excel。

Test Set Accuracy Comparison

C 端看不懂 R² / F1，但看得懂「你的钱亏了多少」——宣传应讲「回撤少 27%」，而非「准确率 55%」。

诚实暴露模型边界

对机构客户，这是 SLA 谈判依据：承诺什么、不承诺什么，有图为证。隐藏缺陷只会上线后翻车；暴露边界反而最快赢得 stakeholder 信任。

技术方案摘要

01

最终方案：KPCA + MLP

组合 准确率 F1 采用
KPCA + MLP 55.4% 59.8% 是
PCA + RF 54.1% 54.1% —
LDA + Logistic 54.1% 51.4% —
  • • F1 差距 > 准确率差距：上涨信号捕捉更优，错过上涨比误判下跌更伤用户
  • • C 端 MVP：可解释性弱可接受；日频策略，训练慢可接受

判断：选型看「失误模式是否最不伤害用户」，不是只看准确率。

02

三种降维并行，而非直接喂 22 特征

学术思路

22 特征全喂，让模型自选——共线性、过拟合、KPCA 算力爆炸。

产品思路

PCA / KPCA / LDA 并行：分别假设线性、非线性、有监督涨跌目标。

结论：KPCA 胜出 → A 股更偏非线性、高噪声。判断：降维是「市场结构假设」，不是数学炫技。

03

严守 T+1 与 0.1% 交易成本

学术取巧

T+0、零成本 → 理论 30% 年化，上线即失效。

产品思路

真实约束下 13.9% 年化，比「假回测」更有说服力。

  • • 信号 shift(1) 实现 T+1；仓位变动扣 0.1% × |Δ仓位|
  • • 训练 / 验证 / 测试按时间 70/15/15 切分，杜绝前视偏差

判断：假回测比低收益更危险。

04

35 个滚动窗口，而非简单 split

单段测试集只代表「某一市场阶段」；采用 252 天训练 + 21 天测试 × 35 窗口。

  • • 得到分布：准确率均值 49.2% ± 12.3%，非单点数字
  • • 阶段不稳定 → 直接定义 V2「模型漂移监测」

汇报「55.4%」须附带「滚动 σ=12.3%」作风险提示。

05

LLM 情绪：识别市场状态，而非提精度

2026 独立测试：加情绪后准确率 53.8%（略低于纯技术）——不等于放弃。

常规思路

精度没涨 → 特征无用 → 砍掉。

PM 思路

情绪做市场状态分类，高/低/平稳期切换不同子模型（V2）。

判断：特征价值取决于放在哪个产品维度，不只看单一指标提升。

技术方案摘要

01

数据采集：Selenium 而非 Requests

房天下页面大量 JS 动态渲染，且有反爬（频率、UA）。Requests 拿不到动态内容且易被识别；付费接口预算为 0。

方案 优点 缺点 采用
Requests 快、省资源 无动态内容、易封 否
Selenium 真实浏览器、抗检测 慢、耗资源 是
付费接口 稳定 单次 ¥3000+ 否

落地：随机 UA（9 种）+ 随机延迟（1–5s）+ 失败重试（5 次）+ 疑难页二轮处理。 结果：14 区共 57,730 条，成功率 99%+，平均每区约 25 分钟。

02

模型选型：Random Forest 而非 XGBoost

模型 CV R² CV MAE R² 标准差
Random Forest 0.7506 109.63 0.0306
XGBoost 0.7474 117.40 0.0298

硬指标几乎打平（精度差 0.32%）。纯技术可互换；PM 视角 RF 胜出：

  • • 可解释性：特征重要性可直接写进产品文案（如「面积决定 76% 价格」），XGBoost 需额外接 SHAP。
  • • 下游成本：B 端会问「为什么这么估」——RF 回答路径更短。

判断：选型看「哪个最容易被产品和客户消化」，不是只看 R²。

03

数据清洗：保留长尾豪宅

学术思路

3σ / IQR 砍掉离群值——R² 立刻好看，但假装豪宅市场不存在。

产品思路

保留合理极端值；高端段失灵反而是分段建模 / 人工兜底的产品信号。

做法：只过滤逻辑错误（总价/单价/面积 ≤0）+ 户型样本 <5 的稀有类型。保留率 62.7%。 判断：清洗目标是反映真实市场，不是让模型好看。

04

评估方式：5×5 重复 K 折

简单 train/test 的 R² 会随随机种子波动，单点数字不可靠。

  • • RepeatedKFold：5 折 × 5 次 = 25 次评估，得到均值 ± 标准差。
  • • 稳定性：标准差 0.0275，上线后不易「突然崩盘」。

对外汇报「R²=0.77」时，需附带「标准差 < 0.03」——单点 R² 是不负责任的。

技术方案摘要

01

双阶段匹配，而非一步到位

1.2M 销量 × 87K 车型笛卡尔积 ≈ 10¹¹ 次比较，直接打分不可行。

暴力做法

1.2M×87K 全量打分 → 数天级；同一车型重复计算。

双阶段

Step1：87K↔价格库建映射（~10⁷）→ Step2：销量查表 join。总量降 4 个数量级，笔记本约 1h 跑完。

判断：避免重复工作比堆 CPU 更重要——架构设计胜过十倍算力。

02

八维度评分：无标准答案的解法

学术思路

纯字符串相似度——「奥迪 A6L」与「奥迪 Q5」可能高分，但语义不同。

多维度评分

8 维独立打分；品牌 4 / 车系 3 / 年排 2 …；排量 ±0.3L 容差；≥8 高 / 5–7 中 / <5 低。

  • • 可解释、可调权、可分层——权重反映业务直觉，不只看代码复杂度
03

多线程 + 向量化

单线程 for + pandas apply 对 87K / 1.2M 要数天。

  • • Step1：ThreadPoolExecutor(8) + Lock + as_completed 进度跟踪 → ~20 分钟
  • • Step2：swifter 行级并行 + NumPy 向量化 + 按品牌预筛选 → ~40 分钟

判断：慢在解释器层；热点交给 NumPy/多线程，Python 能扛百万级。

04

维度失效法处理缺失值

删除 / 填充

删行丢 30%+ 长尾；填充众数会「骗高分」。

维度失效

缺失维不参与也不扣分；按可比较维度计分 → 信息不全自然落入中低置信。

判断：缺失是常态；反映真实可信度，不用假数据制造完整感。

05

输出 5 条战略建议，而非只交 CSV

常规交付

CSV + 描述统计——客户不知从哪看起，数据≠业务交付物。

走到决策

5 条结构化建议（基建 / 10–15万 EV / PHEV / TCO / 分城），每条附数据+政策+落地路径。

判断：客户买的是「接下来怎么办」——从信息到决策，是 PM 与纯分析师的分水岭。

产品化思考

01

目标用户分层：一个模型，三类生意

模型中立（准确率 55.4% 人人相同），但付费方、误判成本、产品形态完全不同——不能「一个模型卖三类客户」。

用户 痛点 付费形态 误判成本
C 端散户 情绪化交易 免费 App + Pro 会员 低 · MVP
B 端券商/私募 缺因子、不愿自研 因子授权 + API 中 · V1.5
机构量化 择时 + 自动交易 策略授权（定制） 高 · V2

同一 KPCA+MLP：对 C 端是参考信号，对机构是决策依据——后者需鲁棒性、SLA、风控、回滚，量级完全不同。

02

产品定位：卖风险控制，不卖准确率

错误叙事

「准确率 55%，比传统高 5pt」→ C 端觉得「我自己猜也行」，机构直接 pass。

正确叙事

「回撤少 27%、Sharpe +57%」——同样收益，风险约为传统的 2/3；焦点从猜对转到亏钱更少。

  • • 回撤是用户能体感的痛点；准确率是抽象数字
  • • 合规友好：不承诺收益，只讲风险控制
  • • 竞品多在卷准确率，主打风控反而稀缺
03

风险与边界：失效检测产品化

35 窗口：准确率 49.2% ± 12.3%；最差窗口 ~30%，部分阶段 Sharpe 仅 -0.04。

  • • 连续 5 日预测错误 →「漂移警报」+ 置信度低、建议观望
  • • 波动率 > 历史 95% 分位 → 防御模式，默认空仓
  • • 月度自动重训，前端展示「模型已更新至 YYYY-MM」
  • • 机构 SLA：不承诺全阶段准确率，承诺长期 Sharpe ≥ 0.6

判断：把「失效检测」做成 feature，比假装全阶段都准更能建立信任。

04

V2 路线图

智能匹配算法 ⚙️

产品决策落到代码的关键一步——把"健康"和"心情"做不同权重；偏好过苛时还有降级方案，避免空白页。

硬过滤

过敏成分 + "今天不想吃"——永不出现。保证安全是底线。

软排序

健康 ×3（长期偏好） + 心情 ×2（临时状态）。权重设计反映优先级。

降级

偏好太苛无匹配 → 候选池前 4 道 + 友好提示。不会"什么都没有"。

核心原则：硬过滤保证安全，软排序保证个性化，降级保证永远有选择。
